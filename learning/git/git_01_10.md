# 2. Git Basic Workflow

The basic workflow I practiced is:

``` text
Edit files
   ↓
git status
   ↓
git diff
   ↓
git add
   ↓
git status
   ↓
git commit
   ↓
git log
   ↓
git push
```

### Important Git layers

``` text
Working Directory
       │
       │ git add
       ▼
Staging Area
       │
       │ git commit
       ▼
Local Repository
       │
       │ git push
       ▼
GitHub Remote Repository
```

This helped me understand that **editing a file, staging it, committing
it, and pushing it are four different operations**.

-   compiled executables

# 8. Git Merge Conflict

I practiced a real merge conflict.

First, I created:

``` text
learning/git/merge-practice.txt
```

with:

``` text
Original line
```

Then I created a branch and changed the same line to:

``` text
Branch version
```

On `main`, I changed the same line to:

``` text
Main version
```

When I ran:

``` bash
git merge merge-conflict-practice
```

Git produced a conflict:

``` text
CONFLICT (content): Merge conflict in learning/git/merge-practice.txt
```

Git inserted conflict markers:

``` text
<<<<<<< HEAD
Main version
=======
Branch version
>>>>>>> merge-conflict-practice
```

I manually resolved the conflict by keeping:

``` text
Main version
Branch version
```

Then:

``` bash
git add learning/git/merge-practice.txt
git commit -m "Resolve merge conflict"
```

### Important lesson

Git cannot always decide how two conflicting changes should be combined.
In those cases, I must manually edit the file, remove the conflict
markers, stage the resolved file, and commit the merge.

# 9. Deleting a Branch Locally and Remotely

I practiced deleting both local and remote branches.

First, I created and pushed:

``` bash
git switch -c delete-branch-practice
git push -u origin delete-branch-practice
```

Then I switched back to `main`:

``` bash
git switch main
```

Deleted the local branch:

``` bash
git branch -d delete-branch-practice
```

Deleted the remote branch:

``` bash
git push origin --delete delete-branch-practice
```

The remote branch was successfully removed.

### Important lesson

These are two separate things:

``` bash
git branch -d branch-name
```

deletes the **local** branch.

``` bash
git push origin --delete branch-name
```

deletes the **remote** branch.

# 10. Git Rebase

I created a branch called:

``` text
rebase-practice
```

I made a commit on that branch and then made another commit on `main`.

After that, I switched back to the practice branch and ran:

``` bash
git rebase main
```

Git successfully replayed the branch commit on top of the newer `main`
commit.

### Before rebase

Conceptually:

``` text
      A---B  rebase-practice
     /
----M---C  main
```

### After rebase

``` text
----M---C---B'  rebase-practice
```

The important point is that the rebased commit gets a **new commit ID**.

### Lesson

`git rebase` is useful for creating a cleaner, more linear history.

# 18. Undo the Last Commit

I practiced:

``` bash
git reset --soft HEAD~1
```

This removed the latest commit from the branch history while keeping its
changes staged.

Then I created the commit again:

``` bash
git commit -m "Practice git stage"
```

### Important lesson

`--soft` keeps the changes in the staging area.

Conceptually:

``` text
Before:

HEAD
 ↓
Commit A
 ↓
Commit B

After git reset --soft HEAD~1:

HEAD
 ↓
Commit A

Changes from Commit B
        ↓
   Staging Area
```

This is useful when I want to redo the latest commit, for example to
change the commit message or adjust what is included.

# 24. Merge vs Rebase

## Merge

``` bash
git merge branch-name
```

Merge combines two lines of development and may create a merge commit.

Example:

``` text
      B---C
     /     \
A---M-------D
```

## Rebase

``` bash
git rebase main
```

Rebase moves/replays commits so the history becomes more linear.

Example:

``` text
A---M---C---B'
```

### Main difference

**Merge preserves the branching history.**

**Rebase rewrites commit history to create a more linear history.**

------------------------------------------------------------------------

# 25. Squash vs Rebase

These are related but not identical.

### Rebase

Can move commits onto another base:

``` bash
git rebase main
```

### Squash

Combines multiple commits into fewer commits:

``` bash
git rebase -i HEAD~3
```

For example:

``` text
Before:
A → B → C → D

After squash:
A → D'
```

where B, C, and D's changes may be combined into one commit.
